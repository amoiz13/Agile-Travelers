# Agile Travellers

Agile Travellers is a Flutter Android prototype for planning Swedish public
transport journeys with the Trafiklab ResRobot API.

## Prototype features

- Station-name autocomplete using ResRobot
- Journey search for Swedish public transport
- Journey leg details for trains, buses, and walking
- CO2 estimates per leg and per journey
- Sorting by departure time, journey duration, transfers, or CO2
- Free-text destination and interest search using Gemini and ResRobot route validation, served through a small API gateway
- On-device travel-interest and seat-comfort preferences
- Android splash screen and Agile Travellers branding

Seat selection and comfort controls are prototype-only: the sample coach and
seat layout are not live operator inventory, and saving preferences does not
reserve a seat. Destination ideas are generated by Gemini; ResRobot is used to
resolve stations and fetch actual journey options.

To search, select an origin and provide a destination, a free-text description,
saved interests, or a combination. With multiple inputs, direct ResRobot routes
and separately tagged Gemini recommendations are shown. Saved interests can be
selected in the travel-interests screen and used without typing a description.
Prompts that Gemini determines are unrelated or not useful for travel
recommendations are rejected with a request to try a travel-related description.
For implementation details, limitations, troubleshooting, and key-handling
guidance, see [the Gemini integration guide](./docs/gemini-integration.md).

## Setup

1. Install Flutter, Android Studio and Node.js 20.12 or newer.
2. Start the gateway, which holds the API keys (the app contains none):

   ```powershell
   cd gateway
   npm install
   copy .env.example .env
   ```

   Edit `gateway/.env` and add a Trafiklab ResRobot key and, for
   interest-based discovery, a Gemini key:

   ```env
   RESROBOT_API_KEY=your_key_here
   GEMINI_API_KEY=your_gemini_key_here
   ```

   ```powershell
   npm run dev     # listens on http://localhost:8787
   ```

3. In another terminal, run the app against the gateway. On the Android
   emulator your computer is reachable at `10.0.2.2`:

   ```powershell
   flutter pub get
   flutter run --dart-define=GATEWAY_URL=http://10.0.2.2:8787
   ```

`gateway/.env` is ignored by Git and must never be committed. The app makes no
direct calls to ResRobot or Gemini and ships without keys; the gateway applies
validation, caching, timeouts and rate limiting. Environment variables, tests
and deployment notes are in
[the Gemini integration guide](./docs/gemini-integration.md).

## Build the Android prototype

```powershell
flutter build apk --release --build-name 0.1.0 --build-number 1 `
  --dart-define=GATEWAY_URL=https://your-gateway.example.com
```

Release builds need an `https://` gateway URL. Without `GATEWAY_URL`, the APK
installs but searches report that the feature is unavailable.

The generated APK is written to
`build/app/outputs/flutter-apk/app-release.apk`.

## Versioning

The current release is `0.1.0+1`, an initial prototype build. The `0.1.0`
tag and GitHub release identify this milestone; later features should use a
new semantic version and Android build number.

Download the prototype APK from [agile-travellers-v0.1.0.apk](./releases/agile-travellers-v0.1.0.apk). Install it on an Android device with Android 6.0/API 23 or newer.
